# Upgrade implementation status

Updated: 2026-07-10

## Product decisions

- GPA: display only the official BYYT GPA. The estimated value remains in the API contract but is not shown by clients.
- Grade transcript export: deferred until the official reporting endpoint is verified.
- Notices: read-only in this release; no local or BYYT read-state write.
- Academic warnings: read-only in this release; no acknowledgement write.
- Cookie login: remains available as an advanced Web login method.

## Completed

- Central BYYT client, classified upstream errors, empty-body handling, response unwrapping, endpoint headers, request serialization, opt-in query retry, single-flight and short course-query cache.
- SQLite session persistence with encrypted upstream cookies, hashed tokens, idle/absolute TTL, session rotation and Cookie/Bearer transports.
- Stable typed APIs for profile, academic context/terms/calendar, grades/official GPA, progress/warnings, schedule, exams, notices and course selection.
- Course preflight semantics (`1` clear, `-9` conflict, `-1` blocked), Origin protection, idempotency keys, bounded replay results and sanitized audit events.
- React and miniapp migration to the new academic contracts, including notices and calendar pages.
- OpenAPI-generated TypeScript types for both clients and CI drift checks.
- Miniapp Bearer authentication and user/schema-versioned page caches.
- Backend, Web, miniapp and repository CI gates; dependency audits; Docker builds; secret scan.
- Frozen backend and frontend container builds, liveness/readiness separation and rollback documentation.
- Campus WiFi implementation left unchanged with a standalone-route smoke test.

## Deliberately retained compatibility

Legacy academic route adapters remain enabled for already-published miniapp versions. New client code no longer calls them. Remove the adapters only after deployed access logs show old-client usage is below the accepted rollout threshold.

## External release gates

The following cannot be completed safely by automated tests:

1. Perform one manually supervised course select/drop/cart acceptance using a designated test account before enabling production writes.
2. Publish and pass WeChat miniapp review, then monitor legacy-route traffic before compatibility removal.
3. Build and publish both images under the same immutable release tag, retaining the previous known-good tag for rollback.

No automated test performs a real BYYT write operation.

## Known non-blocking items

- FastAPI's TestClient emits one upstream Starlette/httpx deprecation warning; project code has no remaining Pydantic deprecation warnings.
- The Web production bundle reports a size warning. It builds successfully; route-level code splitting can be handled as a later performance-only change.
- Web remains on TypeScript 5.9 because `openapi-typescript@7.13` declares TypeScript 5 support. The miniapp remains on TypeScript 7; types for both clients are generated by the locked Web toolchain.
